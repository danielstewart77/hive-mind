# Rollout: per-holder credentials (story 998)

The code refuses the old shared values outright. **Mint every holder's
credential and distribute it before the services restart.** A holder that is
missed is refused the moment comms or lucent comes up on this code.

Order matters: mint while the old code is still running and ignoring the new
table, distribute, then restart.

## 1. Mint, on this workstation

One value per holder. `openssl rand -hex 32` per holder — never reuse one, the
table refuses a duplicate and names the holder it collided with.

Gateway (comms), admin token in hand:

    curl -sX PUT http://127.0.0.1:8426/credentials/<holder> \
      -H "Authorization: Bearer $COMMS_ADMIN_BEARER_TOKEN" \
      -H 'Content-Type: application/json' \
      -d '{"username":"<owner>","token":"<value>","role":"mind"}'

Memory store (lucent), same shape:

    curl -sX PUT http://127.0.0.1:8425/credentials/<holder> \
      -H "Authorization: Bearer $LUCENT_ADMIN_BEARER_TOKEN" \
      -H 'Content-Type: application/json' \
      -d '{"username":"<owner>","token":"<value>","role":"mind"}'

## 2. Distribute

Each holder reads the same variable names it always did. Only the value
changes, and it is now that holder's own.

- Container minds: `COMMS_BEARER_TOKEN` and `LUCENT_BEARER_TOKEN` in that
  mind's own compose fragment or keyring entry.
- Edge minds on this host (skippy): the same two in
  `/home/daniel/Storage/hive-edge-mind-skippy/.env`.
- comms itself: `LUCENT_BEARER_TOKEN` in `nervous-system/.env` becomes the
  `comms` holder's value. Comms no longer has a `COMMS_BEARER_TOKEN` of its
  own to compare against — delete that line rather than leaving a dead value
  in place.

## 3. Restart

hive-lucent takes no fuse. hive-comms carries this conversation, so it gets the
60-second background fuse and one short line.

## 4. The two boxes that cannot be reached

Arnold (Sloan's, 192.168.5.64) and Zach (Aiden's, 192.168.5.62) go dark the
moment the services restart, and stay dark until someone is physically at them.
Neither answers SSH right now.

On each box, signed in as `daniel`:

1. Open the install's `.env`.
2. Set `COMMS_BEARER_TOKEN` to that mind's gateway value from step 1.
3. Set `LUCENT_BEARER_TOKEN` to that mind's memory-store value from step 1.
4. **Delete `COMMS_ADMIN_BEARER_TOKEN`.** This is the point of the exercise.
   It was a skeleton key reaching every conversation and every admin route on
   the hive, and it was in a child's bedroom. Self-registration no longer needs
   it: a mind's own credential registers its own row.
5. Set `MIND_ADMIN_TOKEN` to a fresh per-box value if that box's own admin
   routes are wanted (`PATCH /runtime`, the file editor). Omit it and those
   routes answer 503, which is the safe default.
6. Restart the logon-triggered scheduled task, or log the user out and in.
7. Confirm from here: the mind's row in `GET /broker/minds` should show a
   fresh `last_seen`, which only a successful self-registration produces.

Until step 4 is done on both boxes, requirements 1, 3 and 9 of this story are
true of every holder except those two.
